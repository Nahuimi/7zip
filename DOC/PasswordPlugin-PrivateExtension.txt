Private Password Plugin Extension Notes
--------------------------------------

This document explains how to build a private password-book extension
plugin without publishing the private lookup logic to the public repository.


Short answer
------------

Yes. If you keep the same DLL name and the same exported API,
you usually only need to modify:

  CPP/7zip/UI/PasswordPlugin/

In most cases, private extension logic can be added only in:

  CPP/7zip/UI/PasswordPlugin/PasswordPluginCore.cpp

The host side (7zFM.exe / 7zG.exe / right-click extraction) does not
need to change as long as:

- the DLL file name stays `7zPasswordPlugins.dll`
- the exported function names stay the same
- `Z7_PASSWORD_PLUGIN_API_VERSION` is unchanged, or the host is updated too


What the host currently depends on
----------------------------------

The host only depends on the C ABI declared in:

  CPP/7zip/UI/FileManager/PasswordPluginApi.h

The host loads:

  7zPasswordPlugins.dll

and calls these exports:

- Z7PasswordPlugin_GetApiVersion
- Z7PasswordPlugin_EnsureDatabase
- Z7PasswordPlugin_LoadDatabase
- Z7PasswordPlugin_SaveDatabase
- Z7PasswordPlugin_LookupPassword
- Z7PasswordPlugin_StorePassword
- Z7PasswordPlugin_QueryExtensionByMd5

So if your private DLL keeps this contract, the host does not care
how the private extension logic is implemented internally.


Files to copy
-------------

There are two practical approaches.


Approach A: Keep using the current 7-Zip tree
---------------------------------------------

This is the easiest approach.

Keep these files in your private branch / private repo:

- CPP/7zip/UI/PasswordPlugin/PasswordPluginCore.cpp
- CPP/7zip/UI/PasswordPlugin/PasswordPluginExports.cpp
- CPP/7zip/UI/PasswordPlugin/PasswordPlugin.def
- CPP/7zip/UI/PasswordPlugin/StdAfx.h
- CPP/7zip/UI/PasswordPlugin/StdAfx.cpp
- CPP/7zip/UI/PasswordPlugin/resource.rc
- CPP/7zip/UI/PasswordPlugin/makefile
- CPP/7zip/UI/FileManager/PasswordPluginApi.h
- C/sqlite3.c
- C/sqlite3.h
- C/sqlite3ext.h

If you stay inside the current source tree, you do not need to copy
extra helper code manually, because the makefile already pulls in the
required Common/ and Windows/ sources from the repository.

Recommendation:

- Public repository keeps the local SQLite logic only.
- Private branch adds the private extension implementation.


Approach B: Make a truly standalone private DLL project
-------------------------------------------------------

This is more work, but cleaner.

In that case, the only file you must keep compatible with is:

- CPP/7zip/UI/FileManager/PasswordPluginApi.h

Then you create your own DLL project from scratch and implement the
same exports yourself.

You will also want to vendor:

- sqlite3.c
- sqlite3.h
- sqlite3ext.h

And then reimplement the current behavior without depending on 7-Zip's
internal helper classes.

Recommendation:

- Use Win32 / C++ standard library directly
- Store your DB with SQLite
- Return UTF-16 text through BSTR exactly as the current API expects

This approach avoids depending on 7-Zip internal classes such as
UString, AString, CInFile, and helper wrappers.


Where to add private extension logic
------------------------------------

Recommended place:

  CPP/7zip/UI/PasswordPlugin/PasswordPluginCore.cpp

Recommended flow:

1. Query local SQLite first
2. If not found, host already calls QueryExtensionByMd5()
3. If the extension returns a password, store it back to local SQLite
4. Return the password to the host

That means the best hook point is the plugin-side lookup path.

You can implement it in one of two ways:

- inside `LookupPassword_Direct()`
- inside exported `Z7PasswordPlugin_QueryExtensionByMd5()` and let
  `LookupPassword_Direct()` call it when local lookup fails

Recommended design:

- Keep `LookupPassword_Direct()` as the main orchestration path
- Keep `Z7PasswordPlugin_QueryExtensionByMd5()` as the isolated extension function

That gives you a cleaner split between:

- local storage
- private extension lookup
- host-facing export


When host changes are needed
----------------------------

You do not need to modify the host if you only:

- add HTTP requests
- add authentication
- add local caching
- add retry / timeout logic
- add logging inside the plugin

You only need host changes if you want:

- new UI options in 7zFM for endpoint / token / enable-private-extension
- a different DLL file name
- new exported functions
- a different API version


Recommended private config file
-------------------------------

A private plugin can read a config file next to the DLL, for example:

  7zPasswordPlugins.private.ini

Suggested fields:

[extension]
enabled=1
url=https://your-service/query
method=POST
timeout_ms=5000
auth_header=
auth_token=
cache_success=1
cache_not_found=0

[logging]
enabled=0
path=


Recommended deployment
----------------------

For runtime deployment, keep these files together:

- 7zFM.exe
- 7zG.exe
- 7z.dll
- 7zPasswordPlugins.dll

Optional private files:

- 7zPasswordPlugins.private.ini
- CA certificate bundle if your HTTP layer needs one


Practical recommendation
------------------------

If your goal is "do not publish private lookup logic", the simplest and
lowest-risk way is:

1. Keep the public host unchanged
2. Keep the same `PasswordPluginApi.h`
3. Keep the same DLL name: `7zPasswordPlugins.dll`
4. Implement private logic only in your private copy of:
   `CPP/7zip/UI/PasswordPlugin/PasswordPluginCore.cpp`

So the practical answer is:

Yes, for private extension behavior, in normal cases you only need to modify
`7zPasswordPlugins`.


Current extension API
---------------------

Current API version:

  2

The extension export is:

  Z7PasswordPlugin_QueryExtensionByMd5(
      md5,
      archiveFileName,
      archiveSizeBytes,
      password,
      errorMessage)

Meaning of parameters:

- md5
  ASCII MD5 text of the archive file.

- archiveFileName
  Archive file name including extension.
  Recommended value:
    archive.zip
  Do not rely on directory path being included.

- archiveSizeBytes
  Archive file size on disk in bytes.

Host-side status
----------------

The public host code is already wired to prepare these parameters and
call `Z7PasswordPlugin_QueryExtensionByMd5()` after local password-book
lookup misses.

The public plugin still returns `E_NOTIMPL`, so extension lookup remains
effectively disabled until your private plugin implements it.

Recommended extension request payload fields:

- md5
- file_name
- file_size_bytes
